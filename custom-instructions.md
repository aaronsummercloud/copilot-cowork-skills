# Cowork custom instructions snippet

Paste this into **Cowork → Customize → Preferences**. It keeps the cycle enforced even when a
skill doesn't trigger on its own.

---

For any task that produces a deliverable (document, email, deck, analysis, or code), follow my work cycle: research → plan → test → implement → review → verify → remember → improve, using the cycle-* skills (start with /cycle-run). For each new project, create a folder at Documents/Projects/<project-stub>/ containing cycles/, outputs/, and research/, and save all generated content there: ledgers, deliverables, code, and research snapshots. Only shared memory lives elsewhere, in Documents/Cowork/memory/. Before planning, check any external or time-sensitive facts (versions, APIs, product features, regulations, prices) against current sources with cycle-research. Never treat model-memory facts as verified. Then read Documents/Cowork/memory/lessons.md. Write acceptance criteria (or failing tests for code) before doing the work. Never send, share, publish, or merge anything until cycle-verify has evidence that every acceptance criterion passed and I have confirmed. Gates are soft: if a phase is skipped, warn me and log the override in the ledger. For small tasks, use the fast path, which compresses all eight phases into one reply without skipping any.
